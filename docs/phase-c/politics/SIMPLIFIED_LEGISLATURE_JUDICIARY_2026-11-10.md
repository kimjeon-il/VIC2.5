# VIC2.5 의회·사법부 최소 구현 — 2026-11-10

상태: 별도 작업 브랜치 `work/politics-separation-powers-20261110`에 구현. `main` 병합 전. 기존 3단계 입법, P1/P2/P4 및 일간 12단계 계산 유지.

## 의회: 법률·정권 견제만

- P2 입법과 상·하원 표결, 국가원수 거부권/재의결은 기존 실제 `P4` 정당별 의석을 사용한다. 의회 인원별 표결 AI나 추가 입법점수 원장은 만들지 않는다.
- `p1_vote_no_confidence(country, supporting_parties, today)`: **의회 신임이 필요한 체제**에서만 정상 의회가 행사한다. 실제 하원 의석의 절대과반이 불신임하면 P1 집권 연합을 관리내각으로 표시한다. 국가원수/총리는 이 단계에서 삭제하거나 가상 인물로 교체하지 않는다.
- `P0.no_confidence_votes`는 명시적인 날짜별 명령이다. 국가 정치 AI 역시 실제 하원 의석으로 이미 신임 정족수를 상실한 경우에만 불신임을 제안한다.
- 정부 구성은 기존 P1 익일 정부 교체를 사용한다. 불신임으로 축출된 총리를 그대로 재임명하지 않으며 실제 `PersonAnchor`를 가진 새 정당 지도자가 없으면 관리내각이 유지된다.
- 별도의 연간·월간 예산 법안, 정기 예산 승인·재심의, 셧다운, 청문회, 상임위원회, 의원별 행동/재판은 만들지 않는다. 예산 갈등은 추후 기존 `P1PoliticalEvent`의 사건에서만 다룰 수 있다.

## 사법부: 법률의 실효성만

- **법률 정본**: 기존 P2 선택형 기본법 `judicial_system`의 국가 단위 법률 선택지로 아래 세 상태를 정의한다.
  - `executive_subordinate`: 행정부 종속
  - `limited_independence`: 제한적 독립
  - `independent`: 사법부 독립
- `P1JudiciaryView`는 위 유효 법률을 조회한다. 별도 사법부 원장, 판사, 사건별 재판, 사법 예산을 생성하지 않는다.
- 법률이 없는 역사/구형 시나리오는 **자료 미지정**으로 취급해 기존 지급·채권 회수 규칙을 보존한다. 부재를 행정부 종속으로 해석하지 않는다.
- 독립성별 기초 채권 집행률: 40% / 65% / 85%. 기존 실제 행정·치안 공공서비스가 `staffed` 및 `cash_backed` 조건을 충족하면 분야별 7.5%p씩 가산한다. 범위는 0~100%로 제한된다.
- 신규 임금은 정상적인 실제 임금 지급 절차를 유지한다. **실제 발생 후 30일 이상 미지급된 임금채권**에만 법제도별 집행률을 적용한다. 지급 가능액은 반드시 기존 고용주 현금잔액과 미지급액 이내로 제한한다.
- 기업 파산 시 임금채권 우선 지급을 그대로 유지한다. 이후 실제 지역에 귀속된 기업의 현금 기반 은행채권 회수에도 동일한 집행률을 적용한다. 다국가 사업장으로 귀속 국가가 불명확한 법인에는 잘못된 단일 법역을 적용하지 않는다.
- 60일 이상 실제 미지급 임금채권이 존재하면 최대 30일에 한 번 국가 단위 **정치 사건**을 기록한다. 이는 법원 사건이나 판결을 생성하지 않는다. 실제 지급·채무·재산권은 기존 C 금융 원장에서만 변한다.
- 위헌심사 및 일반 행정명령 재판은 새 시스템을 구축하지 않는다. 반드시 지켜야 할 엔진 원장·법적 유효성 검사는 사법부 독립도에 관계없이 계속 강제한다.

## 데이터와 검증

- 의회 불신임 절차의 저장만 새로운 선택적 확장 `VIC25_PHASEC_P1_CONFIDENCE_1`에 기록한다.
- 사법제도는 기존 P2 법률 선택지에 있으므로 사법부 전용 별도 저장 확장도 없다. `P1Constitution`, `P2Bill`, 인구·금융·의석 직렬화는 변경하지 않는다.
- 집중형 회귀 테스트 `vic25_p1_judiciary_tests`를 CMake에 등록했다. 실제 의석 불신임, 관리내각, 저장-복구, 세 가지 사법 독립도/기존 자료 미지정 상태, 현금 한도 내 미지급 임금 회수를 검증하는 테스트 코드다.
- 전체 빌드·CTest·실행 검사는 여기서 수행하지 않았다. 코드 정적 확인과 GitHub 커밋 반영을 실제 게임 구동 성공으로 해석해서는 안 된다.
