## 전체 통합 원칙

1. **하나의 World, 하나의 월간 StagingWorld, 원장별 하나의 정본.** 실패 시 인구·자금·상품·정치·군사·지역·월 인덱스/ID 발행을 함께 롤백한다.
2. 인구는 `PopulationSlice.count`; 고용은 `EmploymentLedger`; 상품은 `InventoryLedger`; 돈·대출/채무는 `FinancialLedger`; 권리는 `OwnershipLedger`; 법/정부/선거는 `PoliticalRegistry`; 군인 배속은 `ServiceAssignment`; 지역 권한은 `TerritorialJurisdiction`. 다른 부문의 수량/지표는 검증된 조회 뷰/캐시다.
3. **계획·명령·주문·승인·법률 통과·예상 사상자 ≠ 실제 지급·인도·법 발효·인구 전이**. 실제 효과는 그 분야의 유일한 정본에 대응 JournalBatch가 있을 때만 확정한다.
4. 월별 12단계는 [POP-D3](../../pop/D3_RUNTIME.md) 및 [C-D0](../C-D0_COMMON_CONTRACT.md)와 동일. 단계 안의 결정론적 하위 연산으로 정치·군사를 덧붙이며 새 '13번째 월말 단계'를 만들지 않는다.
5. 정책 채택 월 m → 기본 발효 m+1. 단계10 신규동원/제대/전투 사망은 단계2·5·9c의 이미 완료된 고용·임금·선거에 소급 적용되지 않는다.
6. 교전·내전의 실제 사람·장비·보급, 점령지 주민/소유·관할, 국가채무/배상 등은 POP/경제/법률/군사 원장 사이에 **실제 사건 인과관계**가 있어야 한다.
7. 정수 인구·화폐·재고는 보존식/체크산술로; 확률/반올림/시장·전투수치 정책은 규칙버전+재현성 범위를 명시한다. 결과가 경기붕괴·반란·패전이어도 **합법적인 원장·사건 규칙을 지켰으면 정합성 실패가 아니다.**
8. **역사자료·수치 조정·UI/지도는 별개 과제.** 지도 없이 3지역, 2정부, 기업·가구·시장·여러 정치조직과 부대로 먼저 통합 수락한다.

## 검증수준/완료 기준

- **D4-Design:** 계약 문서·정적 링크/스키마/fixture 검산 완료. 이 단계만으로 C++ 통합 시뮬레이션 검증 PASS를 주장하지 않는다.
- **D4-L0 계약선행:** P 설계 정본 GitHub 등록, Phase B 실제 C++ 소스 병합/어댑터, 통합 타입·월간 정본 합의 및 버전 락.
- **D4-L1 원장 통합:** 세계 단위 staging/commit/abort, 대조 검사·이벤트 멱등성/기초 fixture.
- **D4-L2 기능 통합:** E/P/M 연결 48개 검증 중 범위별 테스트/실행 로그 통과.
- **D4-L3 장기/운영:** 1,200개월·결정론/병렬/저장·복구·다중 충격/대규모 성능/Windows 플랫폼을 실제 측정·보고. 정량 성능목표는 기준 하드웨어 실측 후 합의.
- **D4-Complete:** L0~L3 충족 및 운영문서·경고·오류코드·결과 로그/시드·Git 커밋 고정. 실패/미검증 항목을 숨긴 채 완료 선언 금지.
