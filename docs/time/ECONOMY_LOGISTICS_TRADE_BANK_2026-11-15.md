# VIC2.5 후속 경제: 역사적 물류자료·상인 AI·은행 신용

> 2026-11-15 · `work/economy-logistics-merchant-credit-20261115`, 이전 경제 0~3단계 작업 브랜치 위에 구현. **부분 구현 / 세계 전수 자료 미완 / main 미병합**.

## A. 실제 역사 교통자료 및 운송엔진

### 입력한 실제 자료

- `data/historical_transport/rail_openings.tsv`: 1830–1873 미국·영국·벨기에·독일·인도·브라질·남아프리카·일본의 초기 철도 개통 근거 8건. 철도 개통일과 화물운송 개시일을 독립적으로 구분한다. 현 단계에서 별도 근거가 있는 화물운송 개시일은 1건.
- `data/historical_transport/observed_freight_metrics.tsv`: 루이빌–뉴올리언스 하천 선박 운임 관측 2건과 소요일 관측 2건. 원래 출처 단위·기간을 변경하지 않는다.
- `scripts/compile_historical_rail_lifetimes.py`: Python 표준 라이브러리만 사용해 개통 이력의 날짜·출처·중복을 검증한다. 실제 E 프로빈스 물리 연결 `geographic_links.tsv`와 근거가 있는 수동 crosswalk가 제공되면, 기존 `verified_transport_seed.hpp`에서 쓰는 `physical_line_lifetimes.tsv`로 보수적인 월별 유효기간을 생성한다.
- `data/historical_transport/README.md`: 원문·라이선스·연도 범위·남은 자료 범위를 명시한다.

### 기존 물류와 연결

- `quote_daily_freight_path`에 선택적 `documented_services_only` 필터를 추가했다. 잘못된 최저가 가상/구형 간선을 먼저 선택하지 않고 **경로탐색 중에** 출처와 실제 운송서비스 기간이 없는 간선을 제외한다.
- E 프로빈스 실제 형상 연결 및 검증된 G 운송서비스의 월간 수송용량·운임·정확한 일수·효력 시작/종료를 계속 사용한다.
- 운송 계획과 실제 재고 이동은 F/G의 기존 Stage1·Stage7 예약 및 Stage0 도착·중간환적을 재사용한다. 새로운 이중 교통망/재고원장을 만들지 않는다.

**중요 한계:** 역사적 철도 개통 8건은 아직 실제 세계 E 프로빈스 GIS에 공간 결합되지 않았으므로 **게임에서 활성 운송간선 8개를 만들었다는 뜻이 아니다.** 세계적인 역사별 실제 도로/철도/해로·항공·수로운송 네트워크 및 수송능력·운임·시간표 자료는 **미완성**이다. 출처 없는 용량·운임·일수는 추측해서 입력하지 않았다.

## B. 상인·무역회사 AI — Route 없는 신규 거래 탐색

- `phase_gh_market_discovery_impl.hpp`을 추가해 C 실물재고를 보유한 실제 판매자와 지역별 가격·수요를 조회한다. G `Route`가 하나도 없어도 기업·상인이 시장 간 거래를 발의한다.
- 실제 기업 사업장으로부터 기본 상업행위를 발의하거나 P0 `merchant_offices`에 실제 상인의 계정·거점만 등록한다. 상품·매입처·경로는 사전에 명시할 필요가 없다.
- 대상 재고 부족, 판매자 현물, 구매자 현금, 실측 서비스를 통한 도착 원가, 기존 H 관세/금수/쿼터, 최저 기대마진, 운임·수송능력을 확인한다. **하루에 상인 거점별 최대 1건**만 선정한다.
- 수송 전 재고·자금·간선 용량을 예약하고, 실제 C/G 원장으로 매입·수송·관세·운임을 정산한다.
- 이미 진행 중인 같은 상품의 화물과 신규 예약 수량을 차감해 과잉 수입을 방지한다.
- 전 세계 탐색 비용을 줄이기 위해 **상품별 실제 판매재고 색인** 및 **상인 거점별 출발지→목적지 경로 캐시**를 사용한다.
- 신규 상인 행동은 하루 계획에만 존재하며 기존 G/H 스냅샷/원장에 별도의 상인 잔고를 만들지 않는다. 기존 월간 특수 시나리오 API 유지.

**한계:** 목적지 품목에 실제 시장가격과 `target_stock`가 있어야 자율 거래가 성립한다. 상인 법인 설립, 다중 통화별 실제 환율, 완전한 경쟁 주문장·장거리 수요 예측, 선박소유·운송서비스 시뮬레이션은 별도 영역이다. 불확실한 세계 운송 자료가 없으면 상인이 거래를 보류한다.

## C. 은행 신용·투자 및 상환

- `phase_c.hpp`에 기존 복식부기/은행원장의 읽기 전용 `BankCreditView` 및 `BankCreditRule`을 추가했다.
- 신규 투자자금 심사 시 실제 **은행 준비금·예금·대출원금·누적 부실손실**, 기업 **실매출·비용차액·이미 존재하는 차입금·체불임금·파산상태**를 평가한다.
- 기본 통제 범위: 준비금 대비 은행 여신 상한, 기업 매출 대비 총차입 상한, 최소 장부마진, 하루 매출 대비 추가인출 상한. 이 상한은 **VIC2.5 게임용 정책계수**이지 실측된 국가별 역사 금융 비율이라는 주장이 아니다.
- 사전 등록된 미완공 투자/건설비가 실제 기업 현금보다 많을 때에만 P0 Stage1에서 대출을 시도하고, 기존 `lend`를 통해 은행 자산·부채/차입자 예금이 동시에 기록된다.
- 이미 G 무역담보신용이 사용된 기업은 독립된 무담보 자율 대출·상환으로 G 신용잔액과 C 은행원금을 불일치시키지 않는다.
- 수익성 및 유동성이 확인된 기업의 자율 원금상환은 기존 Stage8 `repay`와 채무원장에 기록한다.
- 유효 금리의 근거가 없거나 은행 부실, 체불임금, 실매출·이익 부재인 경우 신규 신용을 발행하지 않는다.

**한계:** 은행 개별법인, 국가별 역사적 지급준비율·담보평가·예금자 행동·금리곡선/외환시장은 아직 미구현이다.

집중 시나리오의 확인 항목:
- `Route`가 없는 상태에서 상인이 실제 국내·해외 가격/재고·서비스 기반 무역 노선을 찾아 구매한다.
- 더 싼 구형 비검증 간선이 존재하더라도, 출처가 있는 철도 서비스만 선택한다.
- 철도가 해당 연도/월에 개통 전이면 운송과 현금지급이 발생하지 않는다.
- 실재고와 운임·구매자 잔액·무역 시점, 운송 중/도착, 스냅샷 복원 후 결정론적 재진행.
- 매출 없는 기업의 신용 거부, 실제 매출기업의 신용한도 내 대출, 원금 상환, 은행 대출 원장 보존.
- 역사 자료의 기계적 일자/출처 확인.

**인수 범위:** 위 소규모 실제 계산 경로에 한정된다. GitHub 전체 CMake/CTest, Windows, 연대별 전 세계 데이터 적재, 백만 POP 및 장기 성능 시험은 수행하지 않았다.

**병합 상태:** 최신 정치 `main`이 이전 경제 작업 브랜치에서 분기한 이후에도 별도 진전되었으므로, 이 브랜치의 `main` 통합은 추후 경제·정치 동시 변경의 조정이 필요하다. 이 작업에서 `main`을 변경하지 않는다.
