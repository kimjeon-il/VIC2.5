# VIC2.5: 핵심 미완료 영역 후속 일별 구현 — 2026-11-07

출발점은 `work/daily-fh-autonomy-integration`이고 기존 월간 독립 시뮬레이션·구형 저장 복구 경로는 별도로 유지한다.

> **중요: 이 변경은 PARTIAL_IMPLEMENTATION / UNVERIFIED다.** 사용자 지시로 **빌드, CTest, GitHub Actions, 벤치마크, 시나리오 회귀, 저장·복구 실행 검사를 전부 생략**했다. 코드가 기록됐다는 사실과 정확히 실행된다는 사실은 다르다. `main`은 변경하지 않았다.

## 1. 임금체불과 기업 파산

**구현된 경로** (`include/vic25/phase_c.hpp`, `p0_daily.hpp`):
- 매일 실제 POP 고용계약의 임금 발생액을 기존 C 복식부기 원장의 **기업 비용·임금채무**와 **가구 임금채권·수익**에 기록한다. 임금이 부족해도 가상 현금지급으로 처리하지 않는다.
- Stage5에서 실제 가용 현금 한도 안에서 임금채권을 부분·전액 상환하고 기존 국가별 원천징수를 적용한다. 이후에도 남은 채무는 유지한다.
- 30일 이상 미상환·유동성 부족 기업은 파산 상태를 기록하고 기존 고용계약을 종료한다. **실물 설비·채권·재고·소유권은 임의 소멸시키지 않는다.** 이미 파산한 기업은 신규 채용/자동생산을 차단한다.
- 저장 및 복구: 선택적 C `VIC25_PHASEC_WAGE_INSOLVENCY_1` 확장. 원장 채권·채무 보존 확인용 불변식 작성.

**잔여:** 압류·경매·채권자 우선순위·회생/청산·민간 은행의 채무불이행 손실·공공 구제정책 전체는 미구현. 30일은 기본 게임 규칙이지 역사적 파산법 적용을 뜻하지 않는다.

## 2. 실제 POP 생일

**구현된 경로** (`phase_b_world.hpp`, `phase_b_dynamics.hpp`, `phase_c.hpp`, `daily_time.hpp`):
- 신규 자연 출생 및 명시적 일별 출생은 정확한 출생일(1~31일)을 **고유한 POP Slice partition별**로 기록한다. 기존 `Demographic.birth_month`와 구형 Binary ABI는 변경하지 않는다.
- 분할/이동/직업 변화 등 POP 이전 시 출생일 메타데이터를 따라 옮기고, 인원 소멸시 제거한다.
- 실제 날짜를 읽는 일간 실행 경로에서 `age_months_slice`로 노동자격·교육/훈련·투표자격·출산자격 등 알려진 정확한 생일을 반영한다. 저장은 선택적 `VIC25_PHASEC_EXACT_BIRTH_DAYS_1` 확장.
- 기존 자료에 **출생월만 있다면** 임의의 출생일을 만들지 않고 해당 월의 정확도까지만 판단한다.

**잔여:** 역사적 대규모 POP 파일의 실제 생일 소급조사는 불가능할 수 있으며 미제공일을 정확한 날짜라고 주장할 수 없다.

## 3. 민간 자율 투자

**구현된 경로** (`phase_d.hpp`, `p0_daily.hpp`):
- 이미 준공되어 가동 가능하고 인허가·기술 적용이 확인된 기존 산업 시설을 합법적인 설계 예시로 사용.
- 실제 수요 부족, 상품 매출과 투입재 시가의 양(+)의 차이, 고용 노동자, 실제 건설 자재 및 소유자 자금을 검토해 **새 공장 확장 공사**를 자율 발의.
- 프로젝트를 등록할 뿐, 새 자본재를 허공에서 만들지 않는다. 실제 건설비·노동·재료·WIP·준공은 기존 Phase C/D 실물·금융원장의 후속 일별 사건으로 처리.

**잔여:** 모든 업종의 신생 기업 설립, 금융기관의 전면적 자율 대출심사, 산업별 기대수익·경기예측, 기술 도입, 지적재산권, 채권자 회수 및 세계 자본시장 등은 아직 완전한 범용 엔진이 아니다.

## 4. 복합 물류

**구현된 경로** (`phase_gh.hpp`, `phase_f.hpp`, `daily_time.hpp`, `phase_gh_snapshot.hpp`):
- G 실물 간선에 mode(도로·철도·해상·하천·항공) 메타와 검증된 `transit_days` 사용. 모드별 실제 지리 연결(인접/공동해역/지리링크)을 확인하고 비용·운송시간·일별 누적 운송용량으로 경로 선택.
- G 일간 화물은 최초 간선으로만 출고하고, **실제로 도착한 다음 중간 허브**에 C InventoryLedger 실물 재고로 입고. 다음 간선의 실제 용량·운임·재고가 확보돼야 다시 출발한다.
- F 명시·자동 운송을 Stage1에 C 실재고/현금·G 간선용량으로 예약해 G 같은 날 거래와 중복 사용하지 않도록 연결하고 Stage7에 한 번만 실제 결제/재고 인도.
- 실제 허브·환적 구간·출발·도착 메타데이터를 G/H 스냅샷 0.7에 저장. 이전 0.2~0.6 저장 판독 분기.
- 인근 실물 재고와 각 운송 경로는 원본 C/G에만 남으며 별도 경제원장을 추가하지 않는다.

**잔여:** 전 세계 모든 실측 간선과 역사적 항만·철도·항공·통행료·시간표·해상보험·정체·예측적 사고 모델, 전세계 30k Province 실제 병렬 경로 탐색은 미완성. 정보가 없는 구간의 일수를 임의 추정하지 않는다.

## 5. 전쟁·평화 AI

**구현된 경로** (`phase_c.hpp`, `phase_gh.hpp`, `p0_daily.hpp`, `phase_gh_snapshot.hpp`):
- 실제 C 군사부대의 국가 소속 및 현재 지역을 별도 출처 메타로 연결; 인구·군수품은 기존 C 원장 그대로 사용한다.
- 실제 H 영토분쟁(Claim/Active Crisis)과 양국 정부, **양측의 현지 배치된 실병력·탄약**이 모두 있을 때만 법적 전쟁 상태 생성.
- 참전 부대 간 전투에는 실탄 소모·실제 POP 사망/부상·전투 기록 적용. 합성 부대나 무근거 전투력 포인트 생성 금지.
- 실제 병력이 전선에서 작전을 못하고 일정 기간 교전이 없으면 합법적 양국 대표로 휴전조약을 발의·비준, 이후 별도 영구 강화조약 발의. 휴전과 종전은 별개 상태와 조약 효력으로 관리.
- G/H 스냅샷 0.6+ 전쟁 상태/조약 상태 기록; GH 0.7에서는 복합 물류를 함께 저장.

**잔여:** 실제 부대 이동/행군·다수전선·공급망·해군/항공·전쟁 목표·군사동맹·전시경제·점령 후 주권정리/배상·협상 전략 등 전면 대전략 전쟁 AI는 미완성. 지역 전투는 사용자가 제공한 지형 정확도를 보유하지 않으면 중립 계수를 사용하며 역사적 정확성을 주장하지 않는다.

## 6. 국가 예산·국채

**구현된 경로** (`phase_c.hpp`, `ledgers.hpp`, `p0_daily.hpp`, `daily_time.hpp`, `phase_c_snapshot.hpp`):
- 국가별 실국고·법정 소득세·관세 수입과 실제 은행대출 원금을 구분. 기존 금융원장 `debt`에 국채·은행대출이 섞이던 것을 별도 은행대출 원금 매핑으로 분리.
- 실제 현금 보유 투자자와 정부 수권이 있을 때만 국채를 발행, 기존 소유권 원장에 증권 보유 기록. **기존 투자자의 돈만** 국고로 옮긴다.
- 실제 일별 이표이자 누적(정수 잔여분 보존)·지급 및 만기 원금 상환은 기존 금융/증권 원장에서 처리하며, 현금 부족 시 채무가 남는다. 신규 소득·통화를 가상으로 만들지 않는다.
- 국가 AI는 설정된 국고 유동성 필요액, 투자자 가용 현금, 발행한도, 이자율·만기일 기준으로 발행 여부 결정. 국가 지정 공공 사업의 기존 제공자에게 실제 보유현금 한도로 예산 집행. 소득세율 증액은 실제 정부·단독 의결정족수 등 앞서 구현한 법적 조건을 사용.
- `VIC25_PHASEC_SOVEREIGN_BONDS_1` 확장을 사용해 실제 정부 채권·차입금·쿠폰 미지급액 저장.

**잔여:** 국가별 완전한 총예산·국채 경매/수익률곡선·국고금융기관·은행 자본규제·수입지출 우선순위/다중 통화·국제자본 유출입은 구현된 자동화 범위를 넘는다. 기존 월간/이전 시대 복합 `debt` 원장은 구형 저장 원본이 세부 원인별로 분해되지 않으면 소급 분리가 불가능하다.
