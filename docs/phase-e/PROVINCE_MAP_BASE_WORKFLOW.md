# 개별 프로빈스 지도 원본 확인과 보정 순서

플레이 가능한 세계 프로빈스 지도는 아직 없다. 첫 단계는 빅토리아 3의
**개별 프로빈스** 색상과 육지·바다·호수 분류, 원본 평면에서 모서리가
아닌 변을 공유하는 관계를 일괄 확인하는 것이다. 주 개수나 주 경계를
프로빈스 대신 쓰지 않는다. 개발용 10k/20k/30k 합성 시험도 실제 지도
규모나 완료 기준이 아니다.

## 로컬 입력 확인

기존 Python 및 Pillow 환경에서 원본 접근과 사용 권한이 있는 작업 폴더로만 실행:

```powershell
python scripts/preflight_province_raster.py --game-dir "D:\...\Victoria 3\game"
```

도구는 `map_data/provinces.png`, `province_terrains.txt`, `default.map`을
읽기만 한다. Pillow 대신 이미 설치된 GDAL Python 환경에서는 같은 명령에
`--png-reader gdal`을 붙인다(8비트 RGB PNG만). 기본 지도 경로와 다른 지정은 거부한다. 지형 종류 전체를 검사하지는
않으며, 해양·호수는 두 파일에서 분류가 일치해야 한다. 주·시나리오 데이터를
읽지 않는다. 색별 픽셀 수, 육지/해양/호수,
네 방향 픽셀 변 접촉 수를 JSON으로 표준 출력에 표시한다. 일치하지 않는
색·중복 등록·물 분류 누락은 거부한다. 설치본의 해양 목록에서 동일한 색이
반복되면 알려 주고 한 번만 센다. 픽셀 변 접촉 수는 실제 거리도,
육로·항로도 아니다. 결과를 파일로 저장할 경우 Git 작업 트리 밖에 보관한다.
공개 입력에는 같은 검사기를 `MAP.png PALETTE.csv` 인자로 쓸 수 있다.
CSV는 `rgb,kind` 두 열과 여섯 자리 RGB, `land`/`ocean`/`lake` 값을 쓴다.

`python tests/test_province_raster_preflight.py`는 합성 PNG와 설치 폴더
형식에서 CLI를 검증한다. 1.13.11 설치본은 별도 읽기 전용 검사에서
8192×3616 픽셀, 등록·관측 동일 40,875색, 육지 40,717 / 바다 106 / 호수 52,
변 접촉 121,648쌍이었다. 다른 버전과 지구본 보정은 검증하지 않았다.
[Paradox 개발일지](https://www.paradoxinteractive.com/games/victoria-3/news/victoria-3-dev-diary-60-modding)는
색과 개별 프로빈스의 대응을 설명한다. [Paradox 이용약관](https://legal.paradoxplaza.com/eula?locale=en)에서
별도 게임으로 원본 지도나 변환 형상을 배포할 권한은 확인되지 않았다.
프로젝트에는 코드와 합성 시험만 둔다. 배포 지도에는 재사용이 허용된
자료 및 독립적으로 만든 형상을 사용하거나 해당 권한을 별도로 확보한다.

## 보정 인수 순서

1. 원본 평면의 좌표계를 실제 기준점과 별도로 남겨 둔 검증점으로 확인한다.
   이미지 크기만으로 경위도, 날짜변경선, 양 끝 연결 또는 극지 범위를
   추정하지 않는다. 해역과 자료가 없는 영역을 별도 상태로 둔다.
2. 구면 타일 한 구역부터 시베리아·날짜변경선 등 실제 이음매를 시험한다.
   같은 프로빈스가 구면에서 끊기거나 자료 밖이 바다로 변하지 않아야 한다.
   육로 인접은 실제 공유 경계만 허용한다.
3. 1836년 사료와 대조해 역사적 국경 및 필요한 해안만 먼저 교정하고,
   기존 [몽니아즈](../../data/geography/review/jussy_monniaz_1836)·[외레순](../../data/geography/review/oresund_1839)
   검토본을 좁은 범위의 비교 사례로 유지한다. 전체 지도를 구간별 손그림으로
   만드는 방식은 쓰지 않는다. 원본 평면의 색상 ID와 VIC2.5 플레이 ID는
   별도로 관리한다.
