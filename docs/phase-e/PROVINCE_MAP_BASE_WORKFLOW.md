# 개별 프로빈스 지도 원본 확인과 보정 순서

플레이 가능한 세계 프로빈스 지도는 아직 없다. 첫 단계는 빅토리아 3의
**개별 프로빈스** 색상과 육지·바다·호수 분류, 원본 평면에서 모서리가
아닌 변을 공유하는 관계를 일괄 확인하는 것이다. 주 개수나 주 경계를
프로빈스 대신 쓰지 않는다. 개발용 10k/20k/30k 합성 시험도 실제 지도
규모나 완료 기준이 아니다.

## 로컬 입력 확인

기존 Python 및 Pillow 환경에서 원본 접근과 사용 권한이 있는 작업 폴더로만 실행:

```powershell
python scripts/preflight_province_raster.py --game-dir "D:\...\Victoria 3\game"
```

도구는 `map_data/provinces.png`, `province_terrains.txt`, `default.map`을
읽기만 한다. Pillow 대신 이미 설치된 GDAL Python 환경에서는 같은 명령에
`--png-reader gdal`을 붙인다(8비트 RGB PNG만). 기본 지도 경로와 다른 지정은 거부한다. 지형 종류 전체를 검사하지는
않으며, 해양·호수는 두 파일에서 분류가 일치해야 한다. 주·시나리오 데이터를
읽지 않는다. 색별 픽셀 수, 육지/해양/호수,
네 방향 픽셀 변 접촉 수를 JSON으로 표준 출력에 표시한다. 일치하지 않는
색·중복 등록·물 분류 누락은 거부한다. 설치본의 해양 목록에서 동일한 색이
반복되면 알려 주고 한 번만 센다. 픽셀 변 접촉 수는 실제 거리도,
육로·항로도 아니다. 결과를 파일로 저장할 경우 Git 작업 트리 밖에 보관한다.
공개 입력에는 같은 검사기를 `MAP.png PALETTE.csv` 인자로 쓸 수 있다.
CSV는 `rgb,kind` 두 열과 여섯 자리 RGB, `land`/`ocean`/`lake` 값을 쓴다.

`python tests/test_province_raster_preflight.py`는 합성 PNG와 설치 폴더
형식에서 CLI를 검증한다. 1.13.11 설치본은 별도 읽기 전용 검사에서
8192×3616 픽셀, 등록·관측 동일 40,875색, 육지 40,717 / 바다 106 / 호수 52,
변 접촉 121,648쌍이었다. 다른 버전과 지구본 보정은 검증하지 않았다.
[Paradox 개발일지](https://www.paradoxinteractive.com/games/victoria-3/news/victoria-3-dev-diary-60-modding)는
색과 개별 프로빈스의 대응을 설명한다. [Paradox 이용약관](https://legal.paradoxplaza.com/eula?locale=en)에서
별도 게임으로 원본 지도나 변환 형상을 배포할 권한은 확인되지 않았다.
프로젝트에는 코드와 합성 시험만 둔다. 배포 지도에는 재사용이 허용된
자료 및 독립적으로 만든 형상을 사용하거나 해당 권한을 별도로 확보한다.

## 보정 인수 순서

1. 원본 평면의 좌표계를 실제 기준점과 별도로 남겨 둔 검증점으로 확인한다.
   이미지 크기만으로 경위도, 날짜변경선, 양 끝 연결 또는 극지 범위를
   추정하지 않는다. 해역과 자료가 없는 영역을 별도 상태로 둔다.
2. 구면 타일 한 구역부터 시베리아·날짜변경선 등 실제 이음매를 시험한다.
   같은 프로빈스가 구면에서 끊기거나 자료 밖이 바다로 변하지 않아야 한다.
   육로 인접은 실제 공유 경계만 허용한다.
3. 1836년 사료와 대조해 역사적 국경 및 필요한 해안만 먼저 교정하고,
   기존 [몽니아즈](../../data/geography/review/jussy_monniaz_1836)·[외레순](../../data/geography/review/oresund_1839)
   검토본을 좁은 범위의 비교 사례로 유지한다. 전체 지도를 구간별 손그림으로
   만드는 방식은 쓰지 않는다. 원본 평면의 색상 ID와 VIC2.5 플레이 ID는
   별도로 관리한다.

## 보정된 구역 한 면 검토

기존 기준점에서 따로 검증한 좌표식과 **검증이 닿는 범위**를 직접 지정한다.
다음은 인자 설명이며 동작 숫자는 예시(8×8 합성 자료용)다.

```sh
python scripts/review_province_cube.py MAP.png PALETTE.csv \
  --bounds -4 -4 4 4 --uv-bounds -0.09 -0.09 0.09 0.09 \
  --size 64 --projection linear --transform 4 1 4 1
```

- PNG·CSV 대신 `--game-dir WORK_COPY` 가능. `--png-reader gdal`은
  기존 Python용 GDAL이 있을 때만 쓴다. 먼저 정식 사전 검사로 전체 PNG와
  등록표를 확인한다. 구면 검토 도구는 요청한 원본 사각형만 검사한다.
- `--bounds`는 서·남·동·북 경위도이고 서쪽과 북쪽을 포함한다. 경도
  랩이나 이음매 없이 +X면 내부만 허용한다. `--uv-bounds`는
  `u_min v_min u_max v_max` 순서이고, 격자 열은 u, 행은 v다.
  +X 방향 공식은 `(1,v,-u)`다. 이 파일 자체는 게임용 타일 형식이 아니다.
- `--transform`은 `X0 XSCALE Y0 YSCALE` 순서이다. 픽셀 외곽 기준으로
  `x=X0+XSCALE*경도`, `y=Y0-YSCALE*변환위도`. `linear`는 위도 그대로,
  `miller`는 `degrees(1.25*asinh(tan(0.8*radians(위도))))`다. 두 값은
  가능한 수식일 뿐 설치 지도 전체의 좌표계라는 뜻이 아니다. `floor`로
  원본 셀을 고르며 RGB 혼합, 빈칸 채움, 맞춤 매개변수 추정은 하지 않는다.
- 한 번에 최대 1024×1024 출력, 최대 원본 200만 셀을 검토한다.
  보고서는 보존된 원본 셀·라벨·네 방향 변 접촉 수와 누락 또는 새 접촉을 센다.
  새 격자의 두 칸이 접하더라도 원본에서 먼 곳에 같은 색 쌍이 있는 것만으로는
  인정하지 않는다. 각 셀 쌍 바로 근처에 실제 네 방향 경계가 있어야 한다.
  두 원본 셀 사이의 격자 거리가 1셀보다 길면 의도적으로 보수적으로 실패 처리한다
  (대각선은 같은 2×2 안에서 변 접촉이 확인되면 허용). 같은 원본 ID의
  구역도 따로 검사한다. 여러 조각이 합쳐지거나 하나가 여러 조각으로 나뉜
  경우, 조각 총수가 같아도 통과시키지 않는다.
- 기본은 표준 출력의 검토 JSON뿐이다. 누락·추가 접촉·셀 경계 불일치가
  있으면 보고서와 종료코드 3만 반환하고 타일을 쓰지 않는다. 잘못된 입력은
  종료코드 2다. `--tile-output PRIVATE.rgbi`를 지정하고 검토가 통과하면
  새 파일에 헤더 없는 행 우선 `R,G,B,kind` 바이트를 저장한다.
  kind 0은 자료 없음, 1은 육지, 2는 해양, 3은 호수다. 기존 파일은 덮어쓰지
  않는다. 완성 파일의 원자적 게시에는 같은 폴더에서 하드 링크를 지원하는
  파일시스템이 필요하다. 지원하지 않으면 타일 생성을 거부하며, 보고서 전용
  실행에는 이 제약이 없다. 원본 색·보정값·변환 결과는 Git 작업 트리 밖에 둔다.
  통과는 이 격자에서 원본 보존을 확인했다는 뜻이지, 실제 해안 고증이나
  게임에서 쓸 이동·해협·인접 관계까지 승인했다는 뜻은 아니다.

`python tests/test_review_province_cube.py`로 합성 CLI 검사를 실행한다.


### 검토 타일 읽기

`province_review_rgbi.hpp`는 경계가 명시된 **단일 검토용 큐브 면**만 읽는다.
파일 외부에서 면 번호(0–5), 가로·세로 크기(각 1–1024), UV 범위
`(u_min, v_min, u_max, v_max)`를 전달한다. 방향 조회는 기존 Phase E 면 규칙과
각 축의 `[min, max)` 범위를 따르며, 범위를 벗어난 방향은 다른 면으로 옮기거나
채우지 않는다. 열은 u, 행은 v이며 각 행은 네 바이트씩 연속이다.
빈 값은 RGB까지 0인 NoData이며, 검정 육지는 별개의 불투명 표본이다.
육지·바다·호수 분류는 RGBA 표시용 색으로 바꾼 뒤에도 원본 분류로 따로 조회할 수 있다.

검사는 `ctest --test-dir BUILD -R '^vic25_province_review_rgbi_tests$'`에서
실행한다. 이 경로는 CPU 진단용이다. 외레순드 전용 OpenGL 경로, 국가·프로빈스
ID, 인접 그래프와 실제 캠페인 데이터는 변경하지 않는다.

### 화면에서 검토 타일 열기

기존 CMake·OpenGL 3.3·GLFW·GLEW 환경에서 명시적으로 열 수 있다.

```sh
cmake -S . -B build -DVIC25_ENABLE_GL=ON
cmake --build build --target vic25_province_review_gl
./build/vic25_province_review_gl PRIVATE.rgbi WIDTH HEIGHT FACE UMIN VMIN UMAX VMAX
```

출력 당시 타일의 가로·세로, 큐브 면 번호(0–5), UV 범위를 그대로 사용한다.
창에서 **1**은 육지(초록), 해양(파랑), 호수(청록), 자료 없음(회색)을 구분하고,
**2**는 원본 RGB 식별색을 혼합하지 않고 표시한다. 검정 육지도 별도로 표시한다.
**Esc**로 닫는다. 타일 한 장을 해당 큐브 면 정면에서 검토하는 개발 도구이며,
캠페인 지도나 역사적 소유권·이동·인접 관계에 연결하지 않는다. 입력 파일은 읽기만 한다.

OpenGL CTest의 `vic25_province_review_rgbi_gpu`는 이 실행 파일의 합성 검토 모드에서
6면의 비대칭 사각 타일을 실제로 그린 뒤 프레임버퍼의 분류색과 식별색을 확인한다.
