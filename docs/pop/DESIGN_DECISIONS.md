## 범위 밖 / 구현 시 추가 의사결정(설계 미확정 아님)

1. 출생·사망·질병의 **수치 모형 및 계수**: 통계 출처·시대별 자료 확정 뒤 보정. 인구 전이의 인터페이스·보존 조건은 이미 확정.
2. 직업별 실제 시간/겸업: 초기에는 1인당 주된 고용계약 하나; 근로시간/FTE 추가는 후속.
3. 가구의 구체적 구성 추정과 부양·소비 계수: 가구 풀 타입은 확정, 구성 추정 데이터는 후속.
4. 선거권·차별·이념 모델의 상세 함수: 상태/제도 분리 원칙만 POP 계약에 포함.
5. 금액·상품수량의 화폐별/상품별 스케일과 가격 민감도: 자료 파일에서 버전 관리, 수치는 테스트로 보정.
6. 희소 셀 고밀도 저장 방식 및 목표 성능(ms/월, GB): 첫 대규모 실제 벤치마크 후 결정.
7. 크로스플랫폼 부동소수점 비트 재현성: 가격 구현 시 별도 numeric contract 필요.
8. 병역 세부 직무·포로 교환·유족·상속 분포: 공통 사건 규약을 이용해 확장.
9. 복수 국적·법적 성별·혼인상태의 정밀 표현: 확장 원장으로 지원, 인구 중복 생성 금지.

## 주의: 현재 골격과 다른 결정

현재 PopKey에는 wealth_band가 포함되고, Pop.cohorts에 인원 원본이 있으며, Health는 배타적 enum이다. 이런 구현은 **legacy 구조**로 유지하지만 새 계약과 동일하다고 주장하지 않는다. 이식 완료 전에는 D0~D3 코드 검증 완료를 선언할 수 없다.
