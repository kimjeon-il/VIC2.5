# POP-D3 — 월별 계산·동시성·분할/병합·성능 계약

상태: **설계 확정 (구현 전)** · 계약 버전: pop-design/1.1
선행: [D0](D0_ARCHITECTURE.md) · [D1](D1_SCHEMA.md) · [D2](D2_TRANSITIONS.md)

## 목표

경제·인구 계산은 월 단위로 진행한다. 월은 **원자적 상태 변경 단위**이며, 계산 중 실패하면 인구·기업·가격·금융·재고 중 일부만 커밋하는 상태를 절대 공개하지 않는다. 현 코드는 월별 단계 호출 골격만 구현하므로 본 계약을 충족한 것이 아니다.

## 단계·데이터 관측 시점

| 순서 | 단계(기존 이름 유지) | 확정 입력/출력과 시간 경계 |
|---:|---|---|
| 0 | opening_snapshot | 전월 확정된 모든 레지스트리/원장을 immutable 월초 상태로 고정 |
| 1 | planning_and_credit | 월초 상태로 생산·정부·운전자금 계획; 실행 가능한 자금/신용 확보 |
| 2 | labor_clearance | 월초 노동 적격 코호트/기존 계약과 기업 수요를 청산; 한 노동자 주된 계약 1개 |
| 3 | intermediate_goods | 실제 원자재 보유자 사이의 주문·가격·재고·대금 청산 |
| 4 | production | 투입 재고·노동·설비 제약에 맞춰 산출·폐기·재고 이벤트 기록 |
| 5 | wages_and_transfers | 확보한 재원으로 임금·세금 원천징수·복지·정부 이전금 실제 지급 |
| 6 | pop_consumption_plans | 당월 실제 받은 소득과 이용 가능 잔액, 가구 공동예산, 자급소비 기반 수요 |
| 7 | final_goods_market | 실제 상품 인도와 대금 청산; 가구·정부·투자재 구매 구분 |
| 8 | closing_accounts | 수익·비용·이자·세금/부채 정합성·유동성 확정 |
| 9 | saving_and_investment | 출자·대출·배당 선언 및 다음 달 가동/투자계획 등록; 선언은 당월 현금 지급이 아님 |
| 10 | pop_demography_and_health | 당월 말 출생·사망·건강·병역·이주·전직/가구 재편 이벤트 적용 |
| 11 | repricing_and_validation | 차월 가격 산출, 전체 원장·인구 불변조건/재현성 검사, 성공 시 월간 상태 커밋 |

**읽기 규칙:** 단계 n은 단계 0 불변 스냅샷 및 이미 확정된 앞 단계(n보다 작은 단계)의 결과만 읽을 수 있다. 당월 받은 임금은 단계 6 소비에 사용 가능하나, 단계 8의 사후 매출을 단계 2의 운전자금으로 소급 사용할 수 없다. 단계 10의 인구/건강 변화는 **다음 달의 노동공급·생계·교육·병력 집계**에 반영된다. 배당 선언은 이후 지급 시점의 금융 거래로 구현한다.

전투 손실 같은 군사 사건은 S0에서는 단계 10의 월말 충격으로 처리한다. 상세 전투 날짜·월중 동원에 따른 인력 소모가 필요한 후속 엔진은 일자/서브틱 이벤트 계약을 추가하되, 월별 결과는 같은 인구 원장을 통해 집계한다.

## 원자적 스냅샷/커밋

논리 API:
1. BeginMonth(world_snapshot, ruleset, seed) → StagingWorld + read-only OpeningSnapshot.
2. 각 단계는 StagingWorld에 명시적 작업 로그/대기 변경을 기록한다.
3. FlushPopulationEvents()는 D2의 검증·고용/금융 원장 동시갱신을 수행한다.
4. Validate(World + EventLog)로 인구·금융·재고·계약·소유지분·참조 정합성을 확인한다.
5. 원자적 Commit(staging) 성공 시에만 month_index 증가와 저장 체크포인트 갱신.
6. 단계 실패/검증 실패 시 Abort(staging) 및 실패 사유 보고; 확정된 월초 상태는 변경되지 않는다.

구현은 copy-on-write·변경 집합 또는 지역 파티션 스냅샷을 사용할 수 있다. **각 단계마다 전체 World를 깊은 복사하는 것은 요구하지 않음**. 단, 일부 쓰기가 원본으로 누출되어 롤백이 불가능한 최적화는 금지한다.

## 인구 셀 분할과 병합

- 분할 발생 조건: 법적/거주 지역·출생월·성별·건강/복무 상태의 실제 변화, 취업/직업 변경, 가구 소속 변경, 정책 계산에 필요한 자격 분리. 선택적 정밀도 확장은 추정오차와 연산비용으로 판단한다.
- 소득/자산 구간만 바뀌었다는 이유로 자동 POP 생성 금지. 분포가 행동에 중요한 경우 자산 분포 모델 또는 정책상 필요한 분할을 사용한다.
- 목적 조합의 활성 셀이 있으면 그곳에 count를 합산한다. 없으면 ID를 발행한다. **이전/합산은 항상 D2 사건으로 추적**.
- 병합 가능: 세 분류 키뿐 아니라 건강 프로필·교육/직업 자격·자산/부채·계약 배분 및 정치적 행동 모델에 필요한 분포가 같은 결과를 내는 집단. 키가 같다는 사실만으로 금융원장/계약이 다른 집단을 무조건 병합하지 않는다.
- 병합 시 event lineage를 보존하고 셀 ID 재사용 금지, 영구 관계의 이전/정규화 성공 후 원본 셀 은퇴.
- 작은 코호트 자동 삭제 금지. 부족한 표본은 근사치와 신뢰도 표시·상태 통합 규칙을 사용하고, 사망·전사 인원은 결코 조용히 생략하지 않는다.

### 분류 조합 폭발 방지

모든 가능 조합을 사전 생성하지 않는다. 활성 인구가 있는 희소 셀 + 인터닝된 동일 분류 프로필 + 지역별 인덱스로 저장한다. 복합 건강 상태를 모든 연령·문화·직업·재산 조합으로 무조건 펼치지 않는다. 필요시 교육/건강의 요약 분포를 사용하되, 특정 사건의 자격 있는 실제 인원 계산을 위해 선택적으로 세분화한다.

구현 초기에는 std::map 기반 골격을 유지할 수 있으나 벤치마크에서 삽입/순회 비용이 커지면 **contiguous storage / struct-of-arrays / flat index / generation counter**로 교체할 수 있도록 외부 API는 반복자/포인터 노출을 제한한다.

## 재현성, 병렬화, 난수, 반올림

- 모든 원장 반영과 글로벌 집계는 안정적 ID 및 정해진 event 우선순위/의존관계 순서로 수행.
- 병렬 worker마다 전역 PRNG를 순차 호출하지 않는다. 시드 스트림은 (world_seed, month_index, phase, entity_id, event_kind, draw_index)로 독립 파생한다.
- 난수 알고리즘의 종류·버전도 세이브에 고정. 같은 실행환경에서 worker 수나 순회 순서가 달라도 결과가 같아야 한다.
- 인구 전이 기대값은 정수/고정소수점 및 누적 잔여량을 사용한다. 배분은 floor + largest remainder, 동률 ID 순서. 반올림 잔여량을 사건 없이 버리지 않는다.
- 금융·인구·재고의 보존 계산은 정수 및 체크된 중간산술을 사용한다. 가격 공식 등 실수 연산의 **비트 수준 다중 플랫폼 재현성은 자동 보장되지 않음**; 결정론적 근사/고정소수점 구현 또는 플랫폼별 명시적 검증을 통해 보장 수준을 따로 정한다.
- 바이트 단위 재현성 검사에는 엔진 버전·컴파일러·플랫폼·규칙 파일·시드·정렬 정책 등을 기록한다.

## 저장/호환성

세이브 헤더 필수: save_schema_version, pop_contract_version, ruleset_version, month_index, calendar_id, world_seed, price/quantity scales, source_provenance_hash. 엔터티/계정/사건에는 안정적 ID가 있고 스냅샷·원장 로그 간 참조무결성을 검사한다.

권장: 전체 스냅샷 + 월별 delta/event journal + 검증된 checkpoint를 조합해 재시작·오류 재현을 지원한다. 체크포인트 주기는 성능 측정 이후 결정하며, 저장된 사건을 replay할 때 이전 달 사건을 두 번 적용하지 않도록 마지막 커밋 ID를 기록한다. 계약 버전이 다르면 명시적 migration을 수행하거나 로드를 거부한다.

## 성능 계측 의무

매월 다음을 측정해 CSV/기계판독 로그로 저장:
- active demographic cohorts / socioeconomic POPs / household pools / population slices 수
- 신규 분할·병합/은퇴 셀 수, 이벤트 처리량, 미세 분할 원인 상위 항목
- 월별·단계별 wall time, CPU time, 최대 메모리, 할당 횟수/바이트
- 각 원장 집계 시간, 원장 인덱스 hit/miss, 지역 간 결제·인구 이동 수
- 월말 불변조건 검사 시간, 실패 코드, 시드·컴파일 정보

벤치마크: (A) 현 S0 3지역/6경제 POP, (B) 수천~수만 희소 셀, (C) **10만·100만 셀** 인공 부하, (D) 1,200개월 반복, (E) 인구 증가·전쟁·유행병·대규모 이주와 같은 분할 스트레스. 장기 성능 목표값(ms/월, GB)은 첫 기준 벤치마크 이후 **측정된 하드웨어 조건**과 함께 결정하며, 수치를 검증 없이 성능 약속으로 확정하지 않는다.

### 단계별 캐싱

해당 인구 셀의 revision과 관련 법률/경제 상태 버전이 바뀔 때만 노동적격 인구·교육 분포·소비 필요·정치적 영향력 등의 캐시를 무효화한다. 버전이 달라진 캐시를 원본으로 채택하는 일은 금지한다. 지역 단위로 분할된 작업자는 다른 지역에 공유 상태를 직접 쓰지 않고 조정 단계로 결과를 제출한다.

## 설계 게이트 D3

- G-D3-1: 월중 실패 시 인구/은행/재고/달 인덱스 모두 월초 상태로 되돌아간다.
- G-D3-2: 당월 소득·자산을 중복 지출하거나 미래 수익을 과거 단계에 적용하지 않는다.
- G-D3-3: 정수 인구가 소멸·증식하는 모든 경로를 D2의 사건이 설명한다.
- G-D3-4: 동일 시드·규칙·초기 상태에서 단일/다중 worker 실행 결과가 일치하도록 정렬/PRNG/반올림 규칙이 정의된다.
- G-D3-5: 희소 셀 폭증을 수치로 관측할 수 있으며 수량을 인위적으로 삭제하지 않고 처리할 수 있다.
- G-D3-6: 버전이 다른 세이브 로드의 migration/거부 행동이 정의된다.

**현재 구현 격차:** 기존 MonthlyPipeline::advance()는 12개 훅을 순서대로 호출하고 마지막에 월 인덱스를 증가시킨다. 상태 스냅샷, 전역 롤백, 분할/병합 이벤트 큐, 실전 성능 계측은 아직 구현되지 않았다.
