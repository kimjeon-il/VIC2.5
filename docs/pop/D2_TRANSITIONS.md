# POP-D2 — 인구·경제 상태 전이/사건 원장 규약

상태: **설계 확정 (구현 전)** · 계약 버전: pop-design/1.1
선행: [D0](D0_ARCHITECTURE.md) · [D1](D1_SCHEMA.md) · 후속: [D3](D3_RUNTIME.md)

## 전이의 단위

인구 셀의 카운터를 임의로 수정하는 API를 게임플레이·경제·보건·군사 모듈에 제공하지 않는다. **모든 인구 변화는 PopulationEvent의 검증된 원자적 집행**으로만 발생한다.

사건 레코드(논리 모델):

| 필드 | 정의 |
|---|---|
| event_id | 전역 고유 ID; 동일 사건 재적용 방지 |
| occurred_month / effective_month | 관측된 월 / 결과를 반영할 월; 미래 사건은 예약 |
| origin_stage / source_system | 발생 단계(보건·경제·군사 등), 원인 식별 |
| kind | 출생·사망·이주·전직·부상·복구·전역·가구이동 등 |
| allocations | 출발 셀 ID·목적 셀 분류 ID·이동 인원(정수) |
| ledger_effects | 고용·지분·예금·세금·재고 등 동반 처리 |
| dependencies | 선행 사건 ID; 동일 월 순서 의존성 명시 |
| expected_revisions | 출발 셀, 고용계약, 자산 계정 등 변경 전 revision |
| rounding_policy | 정수 배분 근거와 잔여량 |
| reason/provenance | 규칙 버전·자료출처·원인 설명 |

PlannedEvent(제안)과 CommittedEvent(실제 집행)는 다른 자료형이다. 사건 발생 근거를 기록하는 보건/군사/인구 원장과 금융 거래 원장은 **같은 event_id/transaction_id**로 묶이며, 서로 별개의 돈·사람을 생성하지 않는다.

## 사건 처리 파이프라인

1. **제안(Propose)**: 월초 스냅샷/당월 확정 거래를 읽고 예상 인원·원인을 계산한다. 불변 원본은 수정하지 않는다.
2. **정수 배분(Allocate)**: 조건을 만족하는 셀의 실제 인원으로 사건 인원을 배분한다. 부족하면 정책에 따른 명시적 비례 축소 또는 오류; 음수 허용 금지.
3. **사전검증(Validate)**: 셀 인구, 동일인 중복, 법적 적격성, 외래키, 자산·계약·원자재·은행 분개, revision과 사건 중복 ID를 함께 검사한다.
4. **준비(Prepare)**: 연결 원장 전체에 필요한 인구/고용/자산/재무 변경을 작성한다. 잔액의 비례이전은 명시적 분포 정책이 있을 때만 허용한다.
5. **스테이징 실행(Apply)**: 작업용 상태에만 집행하고 이벤트 효과를 중복 적용하지 않는다.
6. **완결성 검증(Check)**: 총인구·지역별 인구·각 원장 정합성, 고용, 배당·상속, 셀 count, 사건의 멱등성을 검사한다.
7. **원자적 확정(Commit)**: 스테이징 상태와 이벤트 로그를 함께 최종 확정한다. 오류 시 전체 사건/월 취소; 부분 성공 상태를 공개하지 않는다.

같은 셀의 인구 10명을 서로 다른 두 사건에서 동시에 8명씩 이동하도록 요청했다면, 두 사건을 조용히 모두 적용하지 않는다. 이전된 인원은 이후 사건에 더 이상 존재하지 않으며, 사전 계획을 재배분하거나 정해진 우선순위/Revision 충돌로 거부한다.

## 상태 전이별 규약

| 사건 | 인구 셀 변경 | 의존 원장과 특별 처리 |
|---|---|---|
| Birth | 신규 생후 0개월 코호트의 목적 셀에 +n | 출생아는 nonworker; 가구 풀 명시; 출산 가능성은 의료/정책 분포 추정 |
| NaturalDeath | 출발 셀 -n | 고용·복무·가구 관계 정리, 필요 시 자산/채무의 유산/청산 계정 |
| Migration | 출발 -n, 목적 지역 셀 +n | 거주지역·소비시장·가구·정부/세금 관계 및 자산 이전 규칙 |
| ProfessionChange | 출발 -n, 새로운 경제 POP 셀 +n | 기존 직업·자격·계약 및 전직 비용/소득 연계 |
| JobLoss/JobStart | 실제 계약 변경, 필요하면 경제 POP 셀 이동 | 단순 실직을 직업 분류 제거로 처리하지 않는다 |
| Culture/Religion/LegalChange | 새 인구학 코호트 분류로 n명 이동 | 법적 권리·정책 효과는 다음 계산에서 조회 |
| HouseholdReassignment | 다른 가구 풀 셀로 n명 이동 | 공동예산/돌봄 기록 이관, 가상의 친족관계 생성 금지 |
| Illness/Injury/Recovery | 새 복합 HealthProfile 참조의 코호트로 n명 이동 | 기존 만성 상태 유지, 치료·재활·직무 적합성 갱신 |
| Mobilization/Discharge | 복무상태가 다른 코호트로 이동 | 군사 원장 동기화, 민간 고용과 병력 중복 방지 |
| Captured/Missing/Returned | pow/missing/active/civilian 전이 | 실종·포로를 자동 사망 처리하지 않음 |
| BattleLoss | 전사 인원 -k, 각 부상유형의 목적 셀 +n | 병력·고용·사망통계·장기손상/재활 동시 정리 |

직업이나 건강 변화는 각각 특정 원장에서 상태가 바뀐 것처럼 보이더라도 **실제 사람 수는 출발 셀의 감소와 목적 셀의 증가로만** 변경한다. 인구 보존 이벤트에 출생·사망을 섞지 않는다.

## 전투 손실의 상호배타적 분류

1,000명 현역/건강 셀을 기준으로 전사 50, 급성 부상 180, 장기 기능손상 70, 비부상 700이라면 **기말 총인구는 950명**이다.

- 50명 사망: 셀의 count 감소. 군사 인원 원장/가구 부양/고용·재무 관련 결과를 처리한다.
- 180명 일시 부상: 부상 건강 프로필 셀로 이동. 부상으로 즉시 민간 취업자가 되는 것은 아님.
- 70명 장기 기능손상: 기능 변화 프로필 셀로 이동. 직업별 적격성은 추후 노동규칙으로 판정한다.
- 700명: 기존 인구 프로필 유지.
- 포로/실종은 별도 결과 범주이며 해당 월 전사자에 포함시키지 않는다.

한 사람이 동일 월 전투 사망과 자연사에 모두 집계되지 않도록, **사망의 원인별 집계가 단일 실제 사망 사건을 분할**하도록 한다. 전투 사망이 우선 확정되면 다른 원인의 위험집합에서 제외하거나, 사건별 원인별 위험률을 하나의 경쟁위험 모형으로 결합한다. 동일 인구에 두 개의 독립 사망자 수를 단순 합산하지 않는다.

## 가구·자산·부채의 처리

- 단순 이직은 기존 POP 자산을 재생성하지 않는다. 고용계약만 변경되고 금융 자산은 기존 소유주에 남을 수 있다.
- 코호트 일부가 새로운 경제 POP 또는 allocation_partition으로 이동하면 고용·재산·부채도 **해당 이동자의 실제 분포**에 맞춰 이전해야 한다. 분포가 없는 경우 명시적 추정/할당 정책을 요구하고 기록한다.
- 재산이나 지분을 보유한 POP가 인구 0명이 되면 종료 전에 다른 소유주·유산 정리 계정(estate/suspense)에 자산과 채무를 이전한다. 사망이 일어났다고 자산/부채를 자동 소멸시키지 않는다.
- 가구 풀이 월중에 재배정되는 경우 공동예금은 이미 등록된 소유권과 정책대로 이전한다. 가구 수와 인원 수를 동등하게 계산하지 않는다.
- 병역·건강 변동은 자동으로 수입/손실/세금 거래를 발행하지 않으며, 복지·군인급여·치료비 등의 **제도 규칙이 실제 지급 명령을 낼 때에만** 금융 거래가 기록된다.

## 월별 이벤트와 정수 배분

기초 월의 인구를 기준으로 월말 자연증감·이주·건강 이벤트를 계산하고, 단계별 의존성을 정의한다. 출생아의 당월 경제활동, 월말 부상자의 당월 생산·급여 소급 변경, 전월의 이미 확정된 구매 내역 소급 수정은 금지한다.

실수형 기대인원에서 실제 인원으로 바꿀 때는:
1. (인구 × 확률)을 고정소수점 정밀도로 계산하고 분수 잔여량을 코호트·원인별로 누적한다.
2. 전체 목표 인원수에 맞는 정수 배분을 **가장 큰 잔여량, 동률이면 안정적 ID 순서**로 정한다.
3. 목표 인원수는 위험집합 인원을 넘을 수 없으며, 기존 인구 셀의 계보를 보존한다.
4. 확률적 모형을 쓰는 경우 난수 스트림은 (전역 seed, 월, phase, entity ID, event kind, 순서)로 파생하여 병렬 실행 순서에 영향을 받지 않는다.

## 실패 및 복구

- 범위를 벗어난 계정·인구, 외래키 미존재, 중복 event_id, 음수 count, 중복 소유지분, 불일치 계약은 실행 거부.
- 외부 원장의 기록이 완료되지 않으면 사건 자체를 성공한 것으로 표시하지 않는다.
- 확정 전 실패 시 실제 world state와 month_index는 변하지 않는다.
- 확정된 사건은 취소할 때 역분개/보상 사건을 사용한다. 역사 로그를 지우고 원래 상태가 존재했다고 꾸미지 않는다.

## 설계 게이트 D2

문서상 아래 동작을 모두 명료하게 실행할 수 있으면 D2 설계 완료:
(a) 출생 1·사망 1의 인구 변화, (b) 복수 코호트 사이의 원자적 이주, (c) 재산 보유자의 사망과 유산 계정, (d) 일자리 이직, (e) 전투 50/180/70 손실, (f) 동일 이벤트 두 번 실행의 거부, (g) 두 이벤트의 출발인원 충돌시 롤백.

**현재 상태:** 기존 apply_battle_loss()/transfer_people()는 단독 함수다. event log 및 금융/고용과 통합된 원자적 처리기는 아직 존재하지 않는다.
