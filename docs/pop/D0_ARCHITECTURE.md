# POP-D0 — 개념·식별·원본 데이터 계약

상태: **설계 확정 (구현 전)** · 계약 버전: pop-design/1.1 · 2026-11-03
상위 문서: [POP 설계 색인](README.md) · 다음: [D1 자료형](D1_SCHEMA.md)

## 목표와 용어

VIC2.5의 POP는 개별 인물이 아니라 동질적 인구 집단을 집계하여 의사결정하는 계산 단위다. 설계의 원칙은 **한 사람은 한 월말 스냅샷에서 정확히 하나의 인구 배분 셀에 속한다**는 것이다. 등록된 총인구를 여러 테이블에 독립적으로 보유하지 않는다.

- **DemographicCohort(인구 코호트)**: 거주지·출생월·인구학적 속성과 건강/복무 프로필을 묶는 분류. 자체 인원 원본은 없다.
- **SocioeconomicPop(경제 POP)**: 기본 직업·생계 전략·지역을 공유하는 경제적 행동 단위. 직업은 신분이나 기업 소유권과 다르며 실업해도 유지될 수 있다.
- **HouseholdPool(가구 풀)**: 공동 생활비·돌봄 부담·수요를 집계하는 통계적 가구 묶음. 실제 개인별 가족관계나 혼인 기록으로 오해하지 않는다.
- **PopulationSlice(인구 배분 셀)**: 위 세 분류 ID와 필요 시 별도 자산/계약 배분 partition을 참조하고 정수 인원수(count)를 보유하는 **유일한 인구 수 원본**. 기존 POP에 직업별 어린이와 피고용 인구가 섞이는 문제를 방지한다.
- **PopulationRegistry**: 사전형 분류 레지스트리 + 0명이 아닌 희소 배분 셀 + 역사/이력. 각 분류의 인원수는 배분 셀을 집계한 조회 결과다.

### 기본 연결

    DemographicCohort ─┐
    SocioeconomicPop  ─┼──> PopulationSlice(count: People) ──> 인구 합계·노동공급·소비 집계
    HouseholdPool     ─┘

인구 코호트·경제 POP·가구 풀의 3계층은 데이터 분류 및 행동의 논리 계층이지, 동일한 사람을 세 번 소유하는 계층이 아니다. 독립적인 3차원 전체 조합표는 만들지 않으며 **인구가 존재하는 셀만** 저장한다.

## 책임·원본(Source of truth; 유일한 원본, source of truth)

| 정보 | 유일한 원본 | 파생 뷰/금지사항 |
|---|---|---|
| 거주 인구수 | PopulationSlice.count | 코호트/POP/가구 풀에 별도 쓰기 가능한 총인구 금지 |
| 나이·성별·문화·종교·법적 신분 | DemographicCohortKey | 조회시 셀을 통해 인원 가중합 |
| 질병·부상·기능 상태·복무상태 | HealthProfile 및 코호트 상태/원장 | 건강과 복무를 단일 배타적 enum으로 축약 금지 |
| 직업·생계 유형 | SocioeconomicPopKey | 직업 ≠ 기업 고용 ≠ 자산 소유 |
| 가구 소비·공동 예산 | HouseholdPool과 금융/거래 원장 | 가구 수와 사람 수를 무조건 동일시 금지 |
| 근로 계약·임금 | EmploymentLedger (인구 배분 셀 참조) | 동일인 중복 전일제 고용 금지 |
| 현금·예금·채권·부채·지분 | Financial/OwnershipLedger | POP 상태 안에 잔액 원본 복제 금지 |
| 상품/주문/거래 | Inventory/Market/TradeLedger | 계획 수요를 실제 구매로 취급 금지 |
| 세금·복지 자격 | 정책·FiscalLedger | 자금 지급은 FinancialLedger에서 별도 확정 |
| 사건 발생과 상태 전이 | 인구/보건/군사 이벤트 로그 | 사건 기록과 재무 분개를 동일 화폐로 이중 집계 금지 |

EconomicPop의 수익·소득·자산 분포는 원장이나 명시적인 분포 추정 자료를 바탕으로 계산한다. 평균 재산 구간을 POP 영구 정체성으로 사용하지 않는다.

## ID 수명과 참조 계약

모든 엔터티는 종별 네임스페이스가 있는 **안정적 ID**를 가진다. 인구 셀의 ID는 내부 시스템에서 한 번 발행하면 재사용하지 않는다. 동일 분류 조합이 재생성되더라도 이전에 종료된 셀의 ID를 부활시키지 않고 새 ID와 이전 셀에 대한 계보를 기록한다.

- 한 셀은 한 시점에 인구 코호트·경제 POP·가구 풀을 각각 **정확히 하나씩** 참조한다.
- 각 셀의 세 분류는 동일한 거주지역(residence_region_id)을 가리켜야 한다. 군인 파견지·출정 위치는 별도 군사/이동 원장의 물리적 위치이며 주민의 주소와 동일하지 않을 수 있다.
- 동일한 인구 코호트는 서로 다른 경제 POP·가구 풀에 분산될 수 있고, 동일한 가구 풀은 서로 다른 직업·연령의 셀을 포함할 수 있다. 세 분류가 같아도 실제 소유·고용 분포가 서로 달라야 하는 경우 allocation_partition_id로 셀을 구별한다.
- 신규 전이로 기존 분류를 변경하려면 출발 셀의 인원수를 감소시키고 목적 셀의 인원수를 증가시키는 하나의 원자적 사건을 기록한다.
- 식별자/이력 변경은 분할과 다른 작업이다. 분류 키의 의미가 바뀌면 새 키/버전으로 마이그레이션하고 이전 식별자에 대한 이력을 보존한다.
- 셀 0명은 활성 테이블에서 제거할 수 있지만, 이미 사용한 ID와 이벤트 참조는 tombstone/계보에 남긴다.

## 가구의 모델링 경계

HouseholdPool은 미시적 가족 그래프가 아니다. 모든 사람은 원칙적으로 한 가구 풀에 배정하며, 기숙사·군대 집단거주·보호시설·가구 형태 미상 인구는 **명시적 집단거주/미배정 풀**로 분리한다. 부양·주거·가족 소비를 계산할 때 가구의 구성 비율과 가구 수는 통계적 설명자료로 사용한다.

정확한 혼인·친자관계·상속인을 모르는 경우 임의의 배우자/자녀 연결을 생성하지 않는다. 출생은 실제 가족 ID 대신 가구 풀과 부모 인구집단 추정 규칙으로 배정한다. 상속·유족급여 등에서 정밀한 가족관계가 필요하면 별도의 확률적/명시적 가구 관계 모형을 추가한다.

가구 풀에 부양인구를 포함한다고 해서 이들의 직업이 부모/보호자 직업이 되는 것은 아니다. 미성년자는 적절한 비경제활동 상태/직업 미배정 경제 POP에 연결한다.

## 교차 분야 연동

1. 노동수요는 기업에서, 노동공급의 적격 인원은 인구 셀에서 도출한다. 고용 기록은 셀 ID와 연결한다.
2. POP의 소득은 임금·사업소득·배당·정부이전의 **실제 거래**에서 유도한다. 가구 풀에 공유할 때도 원장에서 명시적으로 이체한다.
3. 소비계획은 가구/경제 POP의 예산 및 실제 소비 필요를 합산해 만들며 시장은 실제 상품/대금을 청산한다.
4. 정부는 인구의 법적 지위와 가구·소득 정보를 읽되 새로운 인구수를 독립 저장하지 않는다.
5. 군인은 주민 인구에 포함되고 민간 노동력과 중복 계산되지 않는다. 전투 손실은 코호트/셀 및 군사 기록을 함께 갱신한다.
6. 정치·교육·보건은 자신의 제도/사건 원장을 가지며 같은 인구 셀을 참조한다.

## 설계 게이트 D0

- G-D0-1: 어떤 시점에도 인구수의 유일한 기록 위치를 지정할 수 있다.
- G-D0-2: 어린이·실업자·현역·부상자를 임금노동 인구와 혼동하지 않는다.
- G-D0-3: 직업 변경·이주·부상 발생이 인구의 중복 생성 없이 정의된다.
- G-D0-4: 금융·고용·소유·가구 인구를 합산해 세계 인구가 증가하는 일이 불가능하다.

**구현 상태:** 이 문서는 신규 목표 계약이다. 기존 C++20의 Pop, PopKey, CohortKey는 아직 이 모델로 변경되지 않았고, D0 완료는 구현 완료를 뜻하지 않는다.
