# S0-POP v1.0 아키텍처 계약

## 목표

POP의 노동·소비·저축·투자·소유·납세·사회 상태를 같은 경제 순환에 연결한다. POP가 모든 정보를 보유하는 방식이 아니라 각 실체의 단일 원본 상태를 별도 원장에 유지하고 POP ID를 통해 결합한다.

## 엔터티와 책임

| 실체 | 소유하는 원본 데이터 | 파생되는 값 |
|---|---|---|
| POP Registry | 인구 ID, 분류키, 인구 코호트 | 총인구, 노동력, 생활수준의 집계 |
| Employment | 기업·정부와 POP 사이의 고용 계약 | 취업자, 임금소득 |
| Firm | 생산시설, 설비, 조업 계획 | 생산가능량, 손익 |
| Inventory/Production | 물품 실제 보유·투입·산출·손실 | 판매 가능량 |
| Order/Trade/Market | 매수·매도 주문, 체결 거래, 차월 가격 | 수요 초과, 체결률 |
| Ownership | 자산/법인의 발행지분과 주주 | 배당청구권 |
| Financial | 자산·부채·자본·수익·비용 계정과 분개 | 예금, 대출, 재무상태 |
| Fiscal | 세금·이전지출에 대한 과세/지급 사유 | 정부 재정 집계 |
| Health/Demographic | 질병·부상·치료·출생·사망·이주 사건 | 사망률, 노동공급 변화 |
| Political (후속) | POP별 정치적 태도·권리·지지 | 선거·정치집단 영향력 |

## ID와 기록 원칙

- 모든 엔터티는 변경되지 않는 안정적 ID를 가진다. 지역 이동·직업 변경은 ID와 변경 이력을 명시한 전이 사건으로 처리한다.
- 각 경제 사건에 고유한 `transaction_id`, 월별 `month_index`와 사건 종류를 부여한다.
- 분개·상품 이동·고용 기록은 같은 사건을 여러 관점에서 기록할 수 있지만, 화폐·물품·인구를 중복 생성하지 않는다.
- 원장은 실제 상태의 진실값이며, POP별 소득·노동력·자산·부채는 필요하면 집계 캐시로 관리한다.
- 월말 단계별 체크포인트를 저장하고 오류가 생기면 해당 월 상태를 커밋하지 않는 *트랜잭션식 커밋*을 최종 구현한다(현 코드에는 아직 없음).

## POP 키와 하위 코호트

POP Key: `(region, culture, religion, profession, livelihood, wealth_band, legal_status)`. 인구 코호트: `(birth_month, sex, health, functional_limits, military_status)`.

취업은 직업과 구분하고, 지분 소유는 직업과 구분한다. 필요하면 경제적 격차가 커진 인구를 분할하며, 분할/병합 시 소유권·금융자산·교육/숙련의 이전 근거를 남긴다.

## 범위 경계

S0는 지도를 사용하지 않는 시험용 지역경제다. 종교·정치·병역·교육·의료 제도의 상세 계산은 이후 추가할 수 있도록 공통 ID와 상태 연결을 우선 정의한다. 원래 S0 v0.2 코드 없이 이번 저장소에서 새 구조를 작성하고 있다.
