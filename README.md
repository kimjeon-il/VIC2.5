# VIC2.5 — POP 중심 역사 대전략 시뮬레이션

**S0-POP v1.0 설계 규약 확정 / 신규 검증용 코드 골격**입니다. 완성된 경제 엔진이 아닙니다.

- 설계: POP 기본 모델, 성별·출생월·건강·장애/부상·복무 코호트, 고용·소유·재고·회계 원장, 월별 12단계 규약.
- 신규 코드: 정수 인구 코호트 분할/이전, 전투 사상자 상태 전이, 간이 복식부기 원장, 실물 재고 원장, 소유지분·고용 기록, 12단계 파이프라인 인터페이스.
- 테스트: 인구 보존 및 전투 피해, 금융 분개 균형, 재고·지분 보존, 처리 단계 순서에 대한 **단위/스모크 테스트**.

## 빌드 및 테스트

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build
ctest --test-dir build --output-on-failure
./build/vic25_demo
```

CMake 3.20+, C++20 컴파일러가 필요합니다. Linux/GCC 14 환경에서 빌드·CTest 1개가 통과했습니다. 다른 운영체제의 빌드/성능 검증은 별도입니다.

### 외부 역사 시작 데이터 시험

`vic25_play --history <시작 파일>`로 소규모 지리 시험을 열어 국가 소속과
인접 관계를 확인하고 날짜를 진행할 수 있습니다. 저장은
`vic25_play --resume-history <저장 파일>`로 이어서 엽니다.
[입력 형식과 사용법](docs/geography/HISTORICAL_START.md).
아래 국가 화면의 **역사 지리 미리보기**에서도 시작 자료를 열고,
국가를 고른 뒤 날짜 진행과 저장·재개를 할 수 있습니다.
이 경로에는 역사 캠페인 경제나 실제 지도 자료가 포함되지 않습니다.

### 지도 없이 국가 운영 화면 실행

먼저 `cmake --build build --target vic25_play --config Release`로 엔진을
빌드한 뒤, Python에 Tk가 이미 포함돼 있는 환경에서 아래와 같이 엽니다.
`python -m tkinter`로 Tk 사용 여부를 확인할 수 있습니다.

```bash
# Linux (실제 빌드 경로에 맞게 조정)
python scripts/play_panel.py ./build/vic25_play
```

```powershell
# Windows (Visual Studio 다중 구성 빌드)
python scripts/play_panel.py .\build\Release\vic25_play.exe
```

A 또는 B를 골라 날짜를 진행하고 국고·법률·시장·전쟁 상태를 확인할
수 있습니다. 광석 관세는 적용되는 법정 한도 안에서만 바뀌며, 바뀐
관세 수입은 실제 거래가 발생할 때 누적 세입에 포함됩니다. A·B 시험
정부는 소득세율(정수 %)을 제출할 수도 있습니다. 적법한 변경은 다음 달
첫날 진행 시 시행되며, 화면에 현재 세율과 예약 세율·시행일을 표시합니다.
터미널에서 같은 명령은 `income-tax <percent>`입니다. 이미 출발한 화물과 도착한 재고를 구분해서 보여줍니다. 저장은 새 파일에
만들고, 불러올 때는 저장한 나라를 선택합니다. Tk가 없으면 기존
텍스트 실행은 계속 쓸 수 있습니다:
`vic25_play --trial tariff-v1 --country A`.

**A·B 예산 시범판**에서는 같은 국가 화면에서 관세·소득세와 함께
공공사업의 하루 지급 한도를 제출할 수 있습니다. 두 사업은 실제 국고와
하루 한도를 나눠 쓰고, 한도는 다음 달 첫날 진행 시 시행됩니다. 0은
두 사업 지급을 중단시키며, 정부의 모든 지출을 막는 설정은 아닙니다.
화면에는 지급액만 표시하며 실제 서비스 성과나 의료 효과를 뜻하지
않습니다. 기존 A·B 관세 시범판 저장은 그대로 해당 시범판에서 엽니다.
터미널은 `vic25_play --trial budget-v1 --country A`, 명령은 `spending-cap <amount>`입니다.

새 예산 시범판에서는 같은 국가 화면의 버튼으로 공공 공구공장 한 곳을
신청할 수 있습니다. 화면에 국고 공사비와 시공사가 구매할 철강의 양·값을
미리 표시합니다. 신청하면 하루가 진행되지만 설비가 바로 생기지는
않으며, 자재 확보와 공사비
지급을 거쳐 준공됩니다. 준공 표시는 설비가 생겼다는 뜻이지, 투입재 없이
공구가 생산된다는 뜻은 아닙니다. 이전 예산 시범판 저장에는 이 공사가
소급 추가되지 않습니다. 터미널 명령은 `public-build`입니다.

**A 입법 시범판**에서는 선거로 배정된 의석을 바탕으로 월 최저임금
법안을 발의할 수 있습니다. 심의 뒤 지지 정당을 고르고, 기준 의석을
충족하면 가결됩니다. 공포와 시행은 구분되며, 화면의 버튼으로 다음
심의일이나 시행일까지 일일 시뮬레이션을 진행할 수 있습니다.
시행된 최저임금은 신규 근로계약에 적용되고,
기존 계약 임금은 자동으로 바뀌지 않습니다. 이 시범판은 기존 예산·관세
시범판과 별도로 열고 저장합니다.

**A 교육 시범판**은 같은 의회 조작으로 학교 금지에서 공립학교
허용으로 바꾸는 별도 시험입니다. 법이 시행되면 학교의 운영 가능
정원과 실제 초등교육 이상 취득 인원을 따로 확인할 수 있습니다. 학교가
있는 지역의 결과와 비편입 비교 지역의 결과를 함께 보여줍니다.
정원은 학생별 배정 인원이 아니며, 등록·출석을 따로 관리하지 않습니다.

**A 공동 캠페인**은 두 나라를 같은 날짜와 저장 파일에서 운영하는
지도 없는 시험판입니다. 플레이어는 A만 조작하고, B는 독립적으로 정책을
결정합니다. A의 소득세율이나 최저임금법을 바꾸려면 선거에서 의석을 얻은
지지 정당을 선택합니다. 화면에서 두 나라의 세율·재정, A의 공공사업 지급액과
두 나라 사이의 운송 중·도착 화물을 확인할 수 있습니다. 새 공동 캠페인에서는
선거 후 과반 정당으로 공구 공장 건설 예산을 한 번 승인하고, 기존 건설 버튼으로
발주할 수 있습니다. 표결만으로 돈이 나가지는 않습니다. 시공사가 강철을
구매하고 인력을 써서 공사를 마치면 A의 같은 국고에서 공사비 20을 지급합니다.
준공은 이후 처리되며, 승인과 공사 진행은 모두 저장됩니다. 건설이 추가되기
전의 공동 캠페인 저장은 원래 상태로 계속할 수 있지만 새 건설 제안은 생기지
않습니다. 기존 개별 시범판은 별도로 열며, 이 캠페인에서 B를 대신 조작할
수는 없습니다.

새 공동 캠페인에서 B가 수출한 광석은 A 제철소에 실제로 도착한 뒤에만
철로 가공됩니다. 공구 공장이 준공되면 같은 지역에서 철과 목재를 사서
공구를 생산합니다. 현지 목공소는 생산된 공구를 자기 자금으로 사고,
들여온 공구와 판재로 목재 부품을 만듭니다. `공동 교역`에서 광석 운송,
두 공장 재고, 목재 공급자 잔액, 공구 판매량과 목공소의 목재 부품 재고를
확인할 수 있습니다. 목재가 다 떨어지면 제철소가 돌아가도 공구 생산은
멈춥니다. 목공소는 시작할 때 가진 판재 한 장을 사용하며, 이후에는
시장에 나온 판재를 직접 삽니다. 벌목장의 원목은 공구공장과 제재소가
각각 돈을 주고 사며, 제재소가 만든 판재는 목공소의 추가 생산에 쓰입니다.
가계는 받은 임금으로 완성된 부품을 삽니다. 공동 교역 화면에서 벌목량,
두 업체가 사용했거나 보유한 원목 수량, 판재 생산량과 실제 부품 거래를
확인할 수 있습니다. 이 경로가 산업 전체의 장기 자립을 뜻하지는 않습니다.
공장·거래 상태는 함께 저장되며, 이전 저장에는 없던 공장·업체를 추가하지 않습니다.
새로 시작한 공동 캠페인에서는 완제품 재고가 목표량에 도달했거나
당일 임금을 지급할 돈이 부족한 공장은 당일 생산용 투입재를 먼저
사지 않습니다. 제철소는 보유 광석과 도착 예정 화물을 합쳐 2개를
채우는 데 필요한 만큼만 추가 주문합니다. 철도 수송 용량과 도착 시간은
그대로이며, 기존 공동 캠페인 저장은 저장 당시 규칙으로 실행합니다.

새 공동 캠페인에서는 선거 후 정당을 골라 A의 일반 공공사업 하루
지출 한도(0~2)를 표결할 수 있습니다. 가결된 한도는 다음 달부터
실제 지급에 반영됩니다. B의 예산과 별도로 승인한 건설비에는 적용되지
않습니다.

A는 광석 수입 관세도 바꿀 수 있습니다. 바뀐 세율은 새로 발송하는
화물에만 적용되고, 이미 운송 중인 화물의 대금은 다시 청구하지 않습니다.
공동 교역 화면에서 현재 세율과 실제 징수액을 볼 수 있습니다.

A는 B에 양국 간 광석 관세 면제를 제안할 수 있습니다. 양국이
비준하면 마지막 비준의 다음 달부터 면제가 적용됩니다. 화면에는 비준
상태와 발효일이 표시됩니다. 법정 세율은 그대로이고, 앞서 징수한 관세를
소급해 돌려주지 않습니다.

원목 단가는 4, 숲의 월 재생량은 8로 맞췄습니다. 새 공동 캠페인을
5월과 6월을 진행한 검증에서는 매달 원목 8개가 팔려 벌목장 임금이
지급됐고 판재·공구·목재 부품은 각각 4개가 생산됐습니다. 부품을 사는
가계의 임금은 별도로 준비된 고용주 자금에서 지급됩니다.

**A 공급망 복구 시범판**은 같은 두 나라의 별도 시험입니다. 1월에는
B의 광석이 철도로 들어오지만, 2월에는 신규 운송 경로가 끊기고 3월에는
더 오래 걸리는 도로 우회 수송이 시작됩니다. 이미 운송 중인 물량과
제철소에 실제로 도착한 재고를 구분하며, 우회로가 열려도 광석이 도착하기
전에는 그 물량으로 철을 생산할 수 없습니다. 화면에는 도로 운임 지급,
철 생산과 판매대금이 표시됩니다. 운송을 직접 지시할 필요는 없습니다.
저장본은 시나리오 목록에서 같은 시범판을 골라 불러옵니다.

**A 민간 증설 시범판**은 기존 공동 캠페인과 별도로 엽니다. 날짜를
진행하면 가계가 식량을 구매하고, 식량 업체는 판매대금으로 증설을
검토합니다. 공사비 지급과 실제 준공, 새로 고용된 직원의 지갑 잔액,
증설 설비 생산 횟수를 따로 표시합니다. 민간 공사에는 별도 건설
버튼이나 국고 발주가 필요하지 않습니다. 저장을 이어서 하려면
시나리오 목록에서 같은 시범판을 고르세요.

**A 가계 소비 시범판**에서는 같은 가격과 생산 조건에서 임금만 다른
두 가구를 비교합니다. 가구는 임금으로 식량과 의류부터 사고, 잔액과
재고가 충분하면 목재 부품도 삽니다. 화면에는 누적 실수령 임금과
구매 수량, 현재 가계 잔액이 표시됩니다. 날짜를 진행하면 생산과 구매는
자동으로 이뤄지며, 저장본은 같은 시범판을 골라 불러옵니다.

**A 철강·건설 시범판**에서는 이미 있는 공공 공구공장 표결·발주
절차를 사용합니다. 예산 표결은 철강 재고가 없어도 할 수 있지만,
발주는 필요한 철강이 현지 시장에 있어야 가능합니다. 제강소가 구입한
철과 석탄으로 철강을 만들고, 발주 뒤 시공사가 건설에 필요한 철강을
삽니다. 화면에는 생산·조달 대기, 철강 생산량과 제강소 판매대금,
공사비 지급과 실제 준공이 각각 표시됩니다. 저장본은 같은 시범판을 골라 불러옵니다.

**공장 시범판**에서는 광석이 제품으로 바뀌다가 재고가 부족해
생산이 멈추는 과정과, 국고 지출이 공공사업 지급처에 들어가는 것을
확인할 수 있습니다. 첫날 국고가 100에서 98로 줄고 지급처에 2가
들어갑니다. 광석이 소진된 다음 날에는 생산 횟수와 완제품 재고가
늘지 않습니다. 이 시범판의 저장은 같은 시범판으로만 불러올 수
있습니다.

화면은 로컬에서만 실행되며 인터넷이나 지도 파일이 필요 없습니다.
모두 가상 검증 시나리오로, 역사 지도나 캠페인이 아닙니다.

### 텍스트 튜토리얼 실행

`cmake --build build --target vic25_play` 후 `./build/vic25_play`를 실행하면
합성 시장 튜토리얼 `market-v1`이 열립니다. 기존 `vic25_demo`와 별개이며
지도 GUI나 역사 캠페인이 아닙니다. 별도 그래픽 라이브러리가 필요하지 않습니다.

- `status`: 현재 날짜, 인구, 국고, 식량 가격·재고, 구매자 현금 확인
- `step 3`: 실제 일간 엔진을 3일 진행
- `buy 2`: 그날 시장 가격으로 식량 2개 구매. 현금이나 재고가 부족하면 그날은 커밋되지 않음
- `save tutorial.sav`: 새 파일에만 저장. 기존 파일은 덮어쓰지 않으며, 저장 위치의 파일시스템이 하드 링크를 지원해야 함
- `./build/vic25_play --tutorial market-v1 --resume tutorial.sav`: 동일한 튜토리얼 정책으로 저장을 이어서 실행
- `help`, `quit`: 명령 안내, 종료

## 개발 원칙

1. POP는 노동·소비·소유·납세·사회·정치의 기반이며, 기업/시장/금융/정부는 독립적인 상태와 책임을 가진다.
2. 금전 거래는 경제주체별 복식부기로, 재고 이동은 물리적 수량 원장으로 기록한다.
3. 직업·소유자·경제적 계급·법적 지위는 같은 개념이 아니다.
4. 성별·연령·건강·장애·부상은 POP의 실제 인구 구성에 반영한다. 장애 자체를 일률적 실업·무능력으로 처리하지 않는다.
5. 동일 초기 상태·규칙·시드라면 같은 결과를 얻어야 한다. 장기 침체와 회계 오류는 구별해서 검사한다.

저장소 이름 `VIC2.5`는 프로젝트의 명칭이며, Victoria 2 게임 코드 사용이나 공식 Paradox 프로젝트를 뜻하지 않습니다.
